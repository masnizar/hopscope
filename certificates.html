Where to get the certificates

  • PSE filesABAP: /usr/sap/<SID>/<INSTANCE>/sec (SAPSSLS.pse = SSL server Standard, SAPSSLC.pse = SSL client Standard, SAPSSLA.pse = SSL client Anonymous, SAPSYS.pse = System PSE, SAPSNCS.pse = SNC). Web Dispatcher: its sec directory. Download via AL11 / CG3Y or copy from the OS.
  • PSE contentCertificates are read when the PSE stores them unencrypted. If none are found, export them from STRUST or run sapgenpse maintain_pk -l -p <pse> and sapgenpse get_my_name -v -p <pse> and load the output text.
  • STRUST exportSTRUST → select PSE → double-click a certificate → Export certificate (Base64 or binary). Own certificate: Certificate → Export.
  • TracesSMICM → trace level 2–3 → reproduce → dev_icm (Web Dispatcher: dev_webdisp). The certificate references (Subject DN / Issuer DN / SerialNum, CCL error blocks) are matched by issuer + serial number to the loaded PSE / certificate files.
  • Cloud ConnectorConfiguration → On Premise → System Certificate / CA Certificate → download (sys_cert.der, ca_cert.der). With the TLS trace on (Log and Trace Files), scc_core.trc shows the backend server certificate and the CA list it accepts for client certificates — load both to see whether the backend accepts the system certificate.
  • Partner certificatesBrowser (padlock → certificate → export) or openssl s_client -connect host:443 -showcerts → save the PEM blocks to a file.
  • PrivacyOnly public certificates are read; private keys are never extracted. Everything stays in this browser.

Findings

Trust check

Simulates whether the selected PSE accepts the other loaded certificates. For SSSLERR_CLIENT_CERT_UNTRUSTED choose the SSL server PSE of the HTTPS port (SAPSSLS.pse or the SSL server identity of the port) and load the client certificate (with its chain). For SSSLERR_PEER_CERT_UNTRUSTED choose the SSL client PSE (SAPSSLC / SAPSSLA / the SSL client identity of the SM59 destination) and load the server certificate of the target. Every link is checked down to the serial number: issuer name, key identifier (AKI ↔ SKI), issuer serial (AKI) and the signature itself.

Client certificate vs. CA list of the server

From the Cloud Connector TLS trace (scc_core.trc with TLS trace on, or the availability check SCCEndpointValidator): the HTTPS backend asks for a client certificate and names the CAs it accepts (Accepted certificate authorities = the certificate list of its SSL server PSE). A client only sends a certificate issued by one of them, otherwise "No client certificate available". For principal propagation the backend must receive the SCC system certificate, or it does not trust the Cloud Connector as reverse proxy. Load scc_core.trc together with sys_cert.der (Configuration → On Premise → System Certificate → download).

Serial number lookup

Serial number from STRUST, sapgenpse, an ICM / Web Dispatcher trace (SerialNum =), SM21 / security audit log, SAML / XML signature (decimal), openssl or a browser — any notation: hex with or without colons, leading zeros, decimal. Shows the certificate, its chain with the serial of every level, and certificates issued by a CA certificate with this serial.

Logon ticket ACL check (STRUSTSSO2)

ABAP systems (ECC / S/4HANA) accept logon / assertion tickets only from systems in the STRUSTSSO2 access control list — identified by system ID, client, subject, issuer and serial number of the issuing system's System PSE certificate. Paste the ACL rows (STRUSTSSO2 → Access Control List, or SE16 table TWPSSO2ACL, tab / "|" / ";" separated) and load the SAPSYS certificate(s) of the issuing system(s).
